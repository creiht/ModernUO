# Bulk Orders

Bulk Orders is a quest-like crafting system that directs players toward completing specific batches of crafted items in exchange for gold, fame, and unique tools or materials. The system has two variants — Blacksmithing and Tailoring — with two tiers: Small Bulk Order Deeds (1-14 items) and Large Bulk Order Deeds (15-50 items, composed of nested small BODs). Bulk Order Books (BOBs) allow players to collect and manage deeds from NPCs or other players.

## BOD Types

### Small BODs (1-14 items)

Small BODs request a single item type with a quantity of 10, 15, or 20. They are generated by NPCs based on the player's skill level and accept a single crafted item per combine.

**Abstract properties** (`SmallBOD.cs`):
- `AmountMax` — maximum items required (10, 15, or 20)
- `AmountCur` — current count of items combined
- `RequireExceptional` — whether items must be crafted with exceptional quality
- `Material` — required crafting material (`BulkMaterialType`)
- `Type` — the item type to craft (e.g., `ChainChest`)
- `Graphic` — item serial number for display
- `Number` — title text ID (e.g., "Chain Cuirass")
- `Complete` — `AmountCur == AmountMax`

### Large BODs (15-50 items)

Large BODs contain multiple item entries (small BOD-like requests). They are completed by submitting completed small BODs (not individual crafted items) that match the large BOD's entries.

**Abstract properties** (`LargeBOD.cs`):
- `Entries` — array of `LargeBulkEntry` objects, each representing one item request
- `Complete` — `true` only if ALL entries have `Amount == AmountMax`
- `Material` — required material (must match all constituent small BODs)
- `RequireExceptional` — must match across all nested small BODs

## BOD Generation

Small BODs are generated by calling `SmallSmithBOD.CreateRandomFor(Mobile from)` or `SmallTailorBOD.CreateRandomFor(Mobile from)`, which:

1. Selects a random item type from the appropriate `SmallBulkEntry` pool (Blacksmith Weapons/Armor or Tailor Cloth/Leather sets)
2. Determines quantity based on skill distribution table
3. Determines material based on weighted chance table (checking skill requirements)
4. Determines exceptional flag based on skill-based chance
5. Sets the title number (`1020000 + graphic` if < 0x4000, else `1078872 + graphic`)

Large BODs are generated by combining multiple small BODs of the same material and quantity into a single deed with multiple entries.

### Item Type Pools (cfg files)

Small BODs pull from 2 .cfg files per profession:

**Blacksmith** — `Distribution/Data/Bulk Orders/Blacksmith/`:
- `armor.cfg` — 20 armor types (ringmail, chainmail, platemail pieces)
- `weapons.cfg` — 28 weapon types (axes, swords, maces, polearms, fencing)

**Tailoring** — `Distribution/Data/Bulk Orders/Tailoring/`:
- `cloth.cfg` — 31 cloth/armor types
- `leather.cfg` — 12 leather/armor types
- `boneset.cfg` — 8 bone armor types
- 12 named outfit sets (farmer, lady, pirate, wizard, etc.) — 6 items each

Large BODs pull from grouped sets:
- `largering.cfg` (6), `largeplate.cfg` (6), `largechain.cfg` (6)
- `largeaxes.cfg` (6), `largefencing.cfg` (6), `largemaces.cfg` (6), `largepolearms.cfg` (6), `largeswords.cfg` (6)

## Reward Calculation

Both Smithing and Tailoring BODs use an abstract `RewardCalculator` base class with two concrete implementations: `SmithRewardCalculator` and `TailorRewardCalculator`.

### Points Formula

Points are computed from the completed BOD and determine gold, fame, and reward tier eligibility.

**Common components:**

```
points = 0

// Quantity bonus (both professions)
if quantity == 10:     points += 10
if quantity == 15:     points += 25
if quantity == 20:     points += 50

// Exceptional bonus
if exceptional:        points += Smith: 200 / Tailor: 100
```

**Smith item type bonus** (Large BODs only, `itemCount > 1`):

| Type Index | Category | Points |
|------------|----------|--------|
| 0 | Ringmail pieces | 200 |
| 1 | Chainmail pieces | 300 |
| 2 | Platemail pieces | 400 |
| 3 | Bardiche/Halberd | 200 |
| 4 | Daggers/Spears | 300 |
| 5 | Axes/Swords/Maces | 400 |

Formula for Smith: `points += min((typeIdx + 1) × 2, 10)` capped at typeIdx=5.

**Tailor item count bonus** (Large BODs only):

| Item Count | Points |
|------------|--------|
| 4 | 300 |
| 5 | 400 |
| 6 | 500 |

**Material bonus:**

| Smith Material | Points | Tailor Material | Points |
|---------------|--------|-----------------|--------|
| Dull Copper | 200 | Spined | 50 |
| Shadow Iron | 250 | Horned | 100 |
| Copper | 300 | Barbed | 150 |
| Bronze | 350 | — | — |
| Gold | 400 | — | — |
| Agapite | 450 | — | — |
| Verite | 500 | — | — |
| Valorite | 550 | — | — |

### Gold Formula

Gold is randomized around a base value from a 3D table:

```
baseGold = goldTable[typeIndex][quantityIndex][materialIndex]
minGold = floor(baseGold × 9/10)
maxGold = floor(baseGold × 10/9)
finalGold = Random(minGold, maxGold)
```

**Smith Gold Table** (`m_GoldTable`) — 14 type indices × 3 quantities × 9 materials:

| Type | Description | Qty 10 base | Qty 20 base (Valorite) |
|------|-------------|-------------|----------------------|
| 0 | 1-part regular | 150 | 1200 |
| 1 | 1-part exceptional | 400 | 4000 |
| 2 | Ringmail regular | 200 | 1500 |
| 3 | Ringmail exceptional | 500 | 5000 |
| 4 | Chainmail regular | 300 | 2000 |
| 5 | Chainmail exceptional | 700 | 7000 |
| 6 | Platemail regular | 500 | 3000 |
| 7 | Platemail exceptional | 1000 | 10000 |
| 8-13 | Weapons (regular/exceptional) | 3000 | 0 |

**Tailor Gold Table** — uses `m_AosGoldTable` (AOS+) or `m_OldGoldTable` (pre-AOS):

### Fame Formula

Both calculators use the same fame formula:

```
fame = (points / 50) × (points / 50)
```

Examples: 200 points → 4 × 4 = 16 fame; 400 points → 8 × 8 = 64 fame; 800 points → 16 × 16 = 256 fame.

### Reward Item Selection

Each `RewardGroup` contains a `RewardItem[]` array. Selection uses weighted random:

```csharp
RewardItem AcquireItem() {
    int totalWeight = Sum(Items[i].Weight)
    int roll = Random(0, totalWeight)
    for each item in Items:
        if (roll < item.Weight) return item
        roll -= item.Weight
    return Items[Items.Length - 1]
}
```

`RewardItem.Construct()` calls the item's `ConstructCallback` delegate to instantiate the actual item.

## Bulk Order Book (BOB)

The `BulkOrderBook` item allows players to collect and organize BODs from NPCs and other players.

### BOB Properties

| Property | Type | Description |
|----------|------|-------------|
| `ItemCount` | `int` | Visual item count (increments every 5 entries) |
| `Level` | `SecureLevel` | Security level for access control |
| `BookName` | `string` | Custom name (max 40 chars) |
| `Filter` | `BOBFilter` | Shared book-level filter settings |
| `Entries` | `List<IBOBEntry>` | All stored entries (max 500) |

### Adding BODs to BOB

Double-clicking a BOD while the BOB is in the player's backpack adds it:

1. Target BOD must be `BaseBOD`
2. BOB must be in owner's backpack
3. Entry count must be < 500 (hard cap)
4. Creates `BOBSmallEntry` or `BOBLargeEntry` wrapper
5. Increments `ItemCount` every 5 entries
6. Original BOD deed is deleted

### Duping Behavior

When a BOB is duped via `OnAfterDuped()`, all BODs are reconstructed from their `IBOBEntry` wrappers using `Reconstruct()`.

### Context Menu

Right-clicking a BOB provides "Name Book" option for renaming (prompt, max 40 characters).

## BOB Filtering System

The filtering system has two filter scopes that operate independently:

| Scope | Storage | Description |
|-------|---------|-------------|
| **Book Filter** | `BulkOrderBook.Filter` | Shared by all users of the book |
| **Your Filter** | `PlayerMobile.BOBFilter` | Per-player personal filter |

### Filter Dimensions

Four filter dimensions, each stored as an `int` (0 = "All/No Filter"):

| Dimension | Value | Options |
|-----------|-------|---------|
| **Type** | `_type` | 0=All, 1=Small, 2=Large |
| **Quality** | `_quality` | 0=All, 1=Normal, 2=Exceptional |
| **Material** | `_material` | 0=All, 1=Smith, 2=Tailor, 3-16=specific material |
| **Quantity** | `_quantity` | 0=All, 1=10, 2=15, 3=20 |

### Material Filter Values

| Value | Material | Notes |
|-------|----------|-------|
| 1 | Smith | Any smithing material |
| 2 | Tailor | Any tailoring material |
| 3 | Iron (None) | Smith + Iron classifier |
| 4 | Dull Copper | Smith |
| 5 | Shadow Iron | Smith |
| 6 | Copper | Smith |
| 7 | Bronze | Smith |
| 8 | Gold | Smith |
| 9 | Agapite | Smith |
| 10 | Verite | Smith |
| 11 | Valorite | Smith |
| 12 | Cloth (None) | Tailor + Cloth classifier |
| 13 | Leather (None) | Tailor + Leather classifier |
| 14 | Spined | Tailor |
| 15 | Horned | Tailor |
| 16 | Barbed | Tailor |

### Filter Application

`CheckFilter()` (`BOBGump.cs`) applies all four dimensions in order:

```csharp
bool CheckFilter(BulkMaterialType mat, int amountMax, bool isLarge, bool reqExc, BODType deedType, Type itemType) {
    var filter = from.UseOwnFilter ? from.BOBFilter : Book.Filter;
    if (filter.IsDefault) return true;

    // Quality: skip if exceptional/normal doesn't match filter
    if (filter.Quality == 1 && reqExc) return false;      // Filter says "Normal" but deed is Exceptional
    if (filter.Quality == 2 && !reqExc) return false;     // Filter says "Exceptional" but deed is Normal

    // Quantity: skip if amount doesn't match
    if (filter.Quantity == 1 && amountMax != 10) return false;
    if (filter.Quantity == 2 && amountMax != 15) return false;
    if (filter.Quantity == 3 && amountMax != 20) return false;

    // Type: skip if small/large doesn't match
    if (filter.Type == 1 && isLarge) return false;
    if (filter.Type == 2 && !isLarge) return false;

    // Material: complex matching with BGTClassifier for cloth/leather/iron
    switch (filter.Material) {
        case 1: return deedType == BODType.Smith;
        case 2: return deedType == BODType.Tailor;
        case 3: return mat == None && BGTClassifier.Classify(deedType, itemType) == Iron;
        case 4-11: return mat == corresponding ore type;
        case 12: return mat == None && BGTClassifier.Classify(deedType, itemType) == Cloth;
        case 13: return mat == None && BGTClassifier.Classify(deedType, itemType) == Leather;
        case 14-16: return mat == corresponding leather type;
    }
    return false;
}
```

### BGTClassifier

`BulkOrderBook.BGTClassifier` classifies item types into three categories for material filtering:
- **Iron** — smithing items made from ore types
- **Cloth** — tailoring items made from cloth
- **Leather** — tailoring items made from leather

### Pagination

BOB display uses slot-based pagination with up to 10 slots per page. A Large BOD entry with N sub-entries consumes N slots. `GetCountForIndex()` and `GetPageForIndex()` handle the slot mapping.

### Vendor Pricing

BOBGump supports purchasing BODs from player vendors. `BODBuyGump.cs` (144 lines) handles the purchase confirmation flow with price display and confirmation.

## Entry Persistence System

Entries stored in BOBs use a separate persistence registry for serialization.

### IBOBEntry Interface

```csharp
interface IBOBEntry {
    bool RequireExceptional { get; }
    BODType DeedType { get; }
    BulkMaterialType Material { get; }
    int AmountMax { get; }
    int Price { get; set; }
    Item Reconstruct();  // Creates the actual BOD from stored data
}
```

### BaseBOBEntry

Abstract base providing shared fields:
- `Serial` — auto-assigned unique serial via `BOBEntries.NewBOBEntry`
- `Created` — DateTime when entry was created
- `Deleted` — deletion flag

Registers/unregisters with the `BOBEntries` singleton for persistence. Thread-safe serialization fields: `SerializedThread`, `SerializedPosition`, `SerializedLength`.

### BOBSmallEntry

Stores small BOD data for reconstruction:
- `_itemType` (Type) — the item type to craft
- `_amountCur` — items already combined (carried from original BOD)
- `_number` — title text ID
- `_graphic` — item serial number

`Reconstruct()` creates `SmallSmithBOD` or `SmallTailorBOD` with stored values.

### BOBLargeEntry / BOBLargeSubEntry

`BOBLargeEntry` stores an array of `BOBLargeSubEntry` objects, each representing one item in the large BOD:
- `_itemType` (Type)
- `_amountCur`
- `_number`
- `_graphic`

`Reconstruct()` creates `LargeSmithBOD` or `LargeTailorBOD` with reconstructed sub-entries.

### BOBEntries Persistence Registry

Extends `GenericEntityPersistence<IBOBEntry>`. Serial range: 0x01 to 0x7FFFFFFF. File name: `BOBEntries`.
- `NewBOBEntry` — returns next available serial
- `Add()` / `Remove()` — manages entity lifecycle

## Submit Flow

### Small BOD Combine Flow

```
1. Player double-clicks SmallBOD
2. SmallBODGump opens showing item info, required amount, material, quality
3. Player clicks "Combine" button
4. SmallBODGump refreshes, calls _deed.BeginCombine(from)
5. BeginCombine checks if Complete; if not, assigns BODTarget to from
6. Player targets a crafted item in their backpack or in the world
7. BODTarget.OnTarget calls _deed.EndCombine(from, item)
8. EndCombine validation:
   a. Check AmountCur >= AmountMax → "already combined" (1045166)
   b. Check item type matches Type (or is subclass) → "not in request" (1045169)
   c. Check material matches (ore types: DullCopper..Valorite) → "not requested ore" (1045168)
   d. Check material matches (leather types: Spined..Barbed) → "not requested leather" (1049352)
   e. Check RequireExceptional and quality → "must be exceptional" (1045167)
9. On success: item.Delete(), AmountCur++, send "combined" (1045170), refresh gump
10. If not Complete, calls BeginCombine again (chains to next combine)
```

### Large BOD Combine Flow

Large BODs are completed by combining completed small BODs (not individual crafted items):

```
1. Player double-clicks LargeBOD
2. LargeBODGump opens showing all item entries and their completion status
3. Player clicks "Combine" button
4. LargeBODGump refreshes, calls _deed.BeginCombine(from)
5. BeginCombine assigns BODTarget to from
6. Player targets a SMALL BOD deed
7. LargeBOD.EndCombine validation:
   a. Check target is SmallBOD → "not a bulk order" (1045159)
   b. Find matching LargeBulkEntry by small.Type → "not a large request" (1045160)
   c. Check exceptional match → "both must be exceptional" (1045161)
   d. Check material match (same ore or leather) → "same ore type" (1045162) / "same leather type" (1049351)
   e. Check AmountMax equality → "different requested amounts" (1045163)
   f. Check small BOD is complete (AmountCur == AmountMax) → "not completed" (1045164)
   g. Check entry not at max → "already combined" (1045166)
8. On success: entry.Amount += small.AmountCur, small.Delete(), refresh gump
9. If not Complete, calls BeginCombine again
```
